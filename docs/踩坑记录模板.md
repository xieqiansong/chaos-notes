# 踩坑记录模板

每篇聚焦一个坑，结构按 `pitfalls/` 现有三篇（如《MySQL 共享表空间改独立表空间》）来。核心是「场景 → 原因 → 解决 → 预防」四段，按需在中间补「表现 / 排查 / 修改 / 复查」，越细越好用。

## 模板

```markdown
# {标题：简明概括踩的是什么坑}

> 分类：{领域 / 技术 / 场景}
> 踩坑耗时：{短/一般/较长 + 简述}
> 关键参数：{可选，记最关键的配置/命令}
> 整理时间：{YYYY-MM-DD}
> 发生时间：{YYYY-MM}

## 场景

{发生了什么：环境、上下文、要做的操作}

## 表现

- {现象描述，必要时用清单列}

## 排查（可选）

{怎么定位的：命令、观察点}

## 根因

- {为什么会踩坑：根本原因}

## 修改（怎么处理）

1. {处理步骤，带命令/代码}
2. {处理步骤}

## 复查（可选）

- {怎么确认已经解决了}

## 预防（可选）

- {避免再犯的措施}
```

## 写作约定

- 语言：中文。
- **发布前清理敏感信息**：日志、路径、内网 IP、账号、密码等一律脱敏或删减。
- 引用的内容标注**参考来源**（原文网址），不搬运他人源码。
- 处于「整理中」的内容用「整理中」标注，不虚构已完成。
- 开头那段元信息（分类/耗时/时间）照着上面格式写，方便回查时一眼看到背景。
