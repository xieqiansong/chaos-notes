# 学习笔记模板

用于中间件/框架/语言（如 Kafka / Redis / Go）的学习记录。结构不固定，按内容自然走，别套死板骨架。

## 定位与原则

- **一篇对一个中间件/框架/语言**，按「能力维度」尽量覆盖全（参考范本：`notes/Kafka学习记录.md`，涵盖安装、简单收发、批量、过滤、事件、幂等、重试死信等）。
- **以实战项目为载体**：依托真实可跑的工程（demo），记录实现思路、关键代码、验证方式与踩坑过程，证明是亲手做出来的。
- **不重述官方文档**：官网已有的概论/概念不重复整理，只在自己实践基础上组织，必要时附官方链接作为参考来源。
- **可验证可运行**：关联工程 clone 可跑，命令/配置真实可达。
- **隐私合规**：不落库真实账号、密码、内网地址等敏感信息。
- **工程引用一律走 GitHub 链接**，不写本地相对路径。

## 模板

结构不强制，下面只是个起点，内容长什么样就怎么分节：

```markdown
# {标题：中间件/框架/主题名}

工程依托：{关联 demo 的 GitHub 链接}

## 1. 安装 / 部署

{怎么起来的：镜像、端口、docker-compose 等}

## 2. {按能力分节，如「简单收发」}

{关键代码片段 + 对应命令行，能跑能验证}

## 3. {下一个能力维度}

{……}

## 踩坑（可选）

- {真实踩过的坑，口语化记下怎么发现的、怎么解决的}

## 参考来源

- {原文网址 / 关联项目}
```

## 写作约定

- 语言：中文。
- **注明适用的中间件/框架版本与参考来源**（原文网址），不搬运他人源码。
- **发布前清理敏感信息**：日志、路径、内网 IP、账号、密码等一律脱敏或删减。
- 处于「整理中」的内容用「整理中」标注，不虚构已完成。
- 语气放开一点，像在给自己记笔记，不用端着写。
