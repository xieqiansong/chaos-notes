# 序列化学习记录

工程依托：[jdk8-serialization-demo](https://github.com/xieqiansong/chaos-java/tree/main/jdk8-platform/jdk8-serialization-demo)（`chaos-java` 仓库，用同一个 `User` 样例模型横向对比 JDK 原生 / Jackson / Kryo 三种方案，纯内存零外部依赖）。

## 1. 安装

```bash
mvn -pl jdk8-serialization-demo -am test    # 纯内存零外部依赖
# 或看控制台「输入→输出」：直接运行 SerializationApplication.main
```

技术栈：Spring Boot 2.7.18 + `jackson-databind` + `kryo` 5.5.0。

## 2. JDK 原生序列化（★★★）

JDK 自带的 `ObjectOutputStream` / `ObjectInputStream`，零依赖、自带完整类型信息，但体积大、性能差、仅 JVM 可用。

- 必须：`User implements Serializable` + `serialVersionUID`。
- 生产坑：体积通常是 JSON 的 3~5 倍；类名/字段名全写进流，**反序列化即「不可信代码执行」入口**（攻击者可构造恶意流），务必配合白名单；跨语言不可用。

## 3. Jackson JSON 文本（★★★）

JSON 是「跨语言、人类可读、schema 宽松」的事实标准，RPC/HTTP/配置几乎都靠它。

- 关键 API：`objectMapper.writeValueAsString(obj)` / `readValue(json, Class)`。
- 健壮性：`FAIL_ON_UNKNOWN_PROPERTIES=false` 容忍字段增减（接口演进不崩）。
- 生产坑：比二进制体积大、CPU 开销高；大对象/高频链路优先用二进制（见 Kryo）。`INDENT_OUTPUT` 仅美化，生产关掉省字节。

## 4. Kryo 二进制（★★★）

JVM 生态最快的二进制序列化之一，体积远小于 JSON/JDK，常用于会话复制、缓存、高性能 RPC。

- 关键 API：`kryo.writeObject(Output, obj)` / `readObject(Input, Class)`。
- class 注册：`kryo.register(User.class)` 用数字 id 替代写全类名，更小更快；本 demo 用 `setRegistrationRequired(false)` 让 `Date`/`List` 等嵌套类型免登记。
- **非线程安全**：同一 Kryo 实例不能被多线程并发用，生产用 `ThreadLocal<Kryo>` 或对象池。
- 生产坑：结果**非跨语言、不可人读**；class 结构变更需谨慎（版本兼容）；注册顺序影响字节布局。

## 体积对比

`ByteSizeUtil` 把结果统一量化为字节数：一般 **JDK > Jackson > Kryo**（JDK 原生通常最大）。

## 踩坑

- **JDK 原生反序列化是 RCE 入口**：必须白名单（`ObjectInputFilter`）；JSON 反序列化关掉 `enableDefaultTyping` 防 RCE。
- **Kryo 非线程安全**：高并发下务必 `ThreadLocal` 或对象池，否则数据错乱。
- **Jackson 容错配置**：`FAIL_ON_UNKNOWN_PROPERTIES=false` 让接口字段增减不崩。
- **选型**：JSON（跨语言可读）与 Kryo（高性能二进制）是生产最常用两种；JDK 原生理解原理即可，新项目基本不首选。

## 进阶方向

- Protobuf / FlatBuffers：跨语言 + 强 schema + 极致体积/性能，IDL 定义、向后兼容靠字段编号。
- Hessian2（Dubbo 默认）、Jackson `Afterburner`/`Jackson-jr` 加速、流式 `JsonParser`/`JsonGenerator`。
- 兼容性治理：`serialVersionUID`、字段增删的向前/向后兼容、版本号灰度。
