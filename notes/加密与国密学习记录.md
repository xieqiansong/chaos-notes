# 加密与国密学习记录

工程依托：[jdk8-crypto-demo](https://github.com/xieqiansong/chaos-java/tree/main/jdk8-platform/jdk8-crypto-demo)（`chaos-java` 仓库，Spring Boot 2.7 + BouncyCastle，用同一段样例明文横向覆盖四类密码学能力，零外部依赖）。

## 1. 安装

```bash
mvn -pl jdk8-crypto-demo test        # 纯内存，零外部依赖
# 或控制台看「输入→输出」：运行 CryptoApplication.main
```

技术栈：Spring Boot 2.7.18 + `bcprov-jdk18on` 1.78（国密靠 BouncyCastle 库）。

## 2. AES 对称加密（★★★）

对称加密金标准：同一把密钥加解密，速度快，适合加密大量业务数据。

- `CBC`：需随机 IV，仅保机密性（被篡改不报错）→ `AES/CBC/PKCS5Padding`。
- `GCM`：认证加密（AEAD），保机密性+完整性，自带 MAC → 推荐默认，用 `AES/GCM/NoPadding`。

生产坑：密钥不硬编码（用 KMS）；IV 每次随机；CBC 无完整性需配 HMAC 或改 GCM；GCM 的 IV 复用会泄露；JDK8 默认限 128 位。

## 3. RSA 非对称加密 + 签名（★★★）

解决「密钥分发」：公钥公开、私钥保密。加密（公钥加密/私钥解密）+ 签名（私钥签/公钥验）。

- 加密：`RSA/ECB/OAEPWithSHA-256AndMGF1Padding`（必须用 OAEP，别用老 PKCS1）。
- 签名：`SHA256withRSA`。

生产坑：**RSA 不加密大块数据**（有长度上限）——正确做法混合加密（RSA 加密临时 AES 密钥，业务数据用 AES）；私钥放 HSM/密钥库。

## 4. SHA-256 摘要（★★★）

把任意数据压成固定长度指纹（单向不可逆），用于完整性校验。

生产坑：**密码绝不能明文/只存 SHA-256**，必须加盐 + 慢哈希（bcrypt/scrypt/Argon2）；MD5/SHA-1 已不安全。

## 5. 国密 SM2/SM3/SM4（★★★）

中国商用密码标准，政务/金融/国企常要求，均由 BouncyCastle 实现：

- `SM4`：对称（128 位密钥），对标 AES → `Cipher("SM4/CBC/PKCS5Padding","BC")`。
- `SM3`：哈希（256 位），对标 SHA-256 → `MessageDigest("SM3","BC")`。
- `SM2`：椭圆曲线非对称，对标 RSA → `KeyPairGenerator("SM2","BC")` + `Signature("SM3withSM2","BC")`。

生产坑：必须注册并指定 `"BC"` 提供者；SM2 用 `SM3withSM2`（先 SM3 再 SM2 签名）；SM4 同样随机 IV。

## 踩坑

- **认证加密优先 GCM**：CBC 被篡改不报错，需额外 HMAC；GCM 篡改会抛 `AEADBadTagException`（demo 验了「篡改即失败」）。
- **RSA 只加密密钥不加密数据**：大块数据超长度上限，用混合加密（TLS 思路）。
- **密码存储别用纯摘要**：加盐慢哈希，见 `jdk8-security-demo`。
- **国密必须指定 BC 提供者**：漏了 `,"BC"` 直接报错。

## 进阶方向

- 混合加密（RSA 加密临时 AES 密钥，业务数据 AES-GCM）。
- KMS / Vault 托管密钥，禁用硬编码，配轮转策略。
- 密码存储用 bcrypt/scrypt/Argon2 加盐慢哈希。
- 合规：金融/政务优先国密套件（SM2/SM3/SM4/SM9），证书用国密 CA。
