# 定时任务学习记录

工程依托：[jdk8-scheduler-demo](https://github.com/xieqiansong/chaos-java/tree/main/jdk8-platform/jdk8-scheduler-demo)（`chaos-java` 仓库，用同一份样例 Job 横向对比 @Scheduled / Quartz / XXL-JOB 三种方案，除 XXL-JOB 需外部 admin 外零外部依赖）。

## 1. 安装

```bash
mvn -pl jdk8-scheduler-demo test    # @Scheduled / Quartz 纯内存；XXL-JOB 仅反射断言，零外部依赖
# 控制台观察 @Scheduled 后台触发：运行 SchedulerApplication.main
```

技术栈：Spring Boot 2.7.18 + `spring-boot-starter-quartz` + `xxl-job-core` 2.4.0。

## 2. @Scheduled 单进程轻量（★★★）

痛点：周期性小任务（缓存预热、心跳、临时清理）不值得上分布式调度，一个注解搞定。关键 API：`@EnableScheduling` + `@Scheduled(...)`。

三种触发模型（高频考点）：

- `fixedRate`：以上一次**开始**为基准，固定频率（任务耗时 > 间隔会重叠）。
- `fixedDelay`：以上一次**结束**为基准，结束后等固定间隔（绝不重叠）。
- `cron`：cron 表达式精确控制（如每天 0 点）。

生产坑：默认单线程，长任务阻塞后续；多实例部署会**重复执行**（需集群去重 → 见 XXL-JOB）；`fixedRate` 超时后会「追赶式」连续触发。

## 3. Quartz 功能完备（可持久化）（★★★）

痛点：`@Scheduled` 不能动态增删任务、不能持久化、错过触发无策略。Quartz 用「Job（做什么）+ Trigger（何时做）」解耦。关键 API：`SchedulerFactory → scheduleJob(JobDetail, Trigger) → start()`。

本 demo 用**内存 RAMJobStore**（零外部依赖）演示核心；生产要持久化/集群时换成 `JobStoreTX` + 数据库。

生产坑：必须配 misfire 策略；线程池默认 10，长任务会饿死其他任务；集群需共用数据库 + 同 `instanceName`。

## 4. XXL-JOB 分布式调度中心（★★★）

痛点：`@Scheduled`/Quartz 在多实例下会重复执行、无法统一管控（启停/重试/分片/告警）。XXL-JOB 把「调度」与「执行」分离：admin 统一分发，天然支持集群去重、分片广播、动态启停。

关键组件：`XxlJobSpringExecutor`（执行端，向 admin 注册）+ `@XxlJob("任务名")` 处理器。

本 demo 仅含**执行端**；admin 是独立 Web 服务（需数据库）。执行端 Bean 用 `@ConditionalOnProperty(xxl.job.admin.addresses)` 包裹——没配 admin 时应用照常启动。生产坑：executor 必须能连 admin；分片任务需自己按 `shardIndex/total` 切数据；任务需幂等。

## 踩坑

- **多实例重复执行**：`@Scheduled`/Quartz 单机 OK，多实例会重复跑；统一管控上 XXL-JOB。
- **@Scheduled 默认单线程**：长任务阻塞后续任务，必要时自定义 `TaskScheduler` 线程池。
- **fixedRate 追赶触发**：超时后会在下一个窗口连续补触发，留意幂等。
- **Quartz 必须配 misfire 策略**：错过触发的行为不配置会出乎意料。
- **XXL-JOB 分片要自己切数据**：框架只给 `shardIndex/total`，数据分片逻辑业务自写。

## 进阶方向

- 动态调度：Quartz `scheduler.scheduleJob` 动态增删；XXL-JOB 在 admin 界面/API 动态管理。
- 持久化与集群：Quartz `JDBC JobStore`；XXL-JOB admin 自带数据库，executor 水平扩展。
- 高可用：admin 集群/DB 共享；executor 多实例时 XXL-JOB 自动去重，Quartz 集群靠 DB 行锁。
- 可观测：任务执行结果、耗时、失败告警接入监控。
