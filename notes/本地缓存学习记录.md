# 本地缓存学习记录

工程依托：[jdk8-localcache-demo](https://github.com/xieqiansong/chaos-java/tree/main/jdk8-platform/jdk8-localcache-demo)（`chaos-java` 仓库，Spring Boot 2.7 + Caffeine 2.9.3，纯内存零外部依赖，是后续 A 类 demo 的标杆模板）。

## 1. 安装

无中间件、无需 Docker，跑测试或 `main` 即可：

```bash
mvn -pl jdk8-localcache-demo -am test
# 或看控制台「输入→输出」：IDE 直接执行 DemoApp.main
```

技术栈：Spring Boot 2.7.18 + `spring-boot-starter-cache` + `caffeine` 2.9.3（JDK8 用 2.x；JDK11+ 才用 3.x）。

## 2. 基础读写（★★★ 高频）

把热点对象放进堆内缓存，读时直接从内存取，跳过 DB/Redis。

```java
Cache<String, User> cache = Caffeine.newBuilder().build();
cache.put("1", User.sample(1));
User u = cache.getIfPresent("1");   // 命中，不触发加载
cache.invalidate("1");              // 失效
```

- 写 `put` / 读 `getIfPresent` / 失效 `invalidate`，每个 `User` 由 `User.sample(id)` 工厂造出。

## 3. 写入过期（★★★ 高频）

本地缓存最怕「脏数据一直不更新」。`expireAfterWrite` 让写入后经过固定时间自动失效，实现最终一致。

```java
Caffeine.newBuilder().expireAfterWrite(2, TimeUnit.SECONDS).build();
// 还有 expireAfterAccess（空闲过期）、expireAfter（自定义读写后过期，最灵活）
```

## 4. 容量淘汰（★★★ 高频）

堆内缓存必须限制大小，否则无限增长 OOM。Caffeine 默认用 **W-TinyLFU** 淘汰策略，比传统 LRU 命中率更高（能识别「短暂突发」与「真正热点」）。

```java
Cache<String, User> cache = Caffeine.newBuilder()
    .maximumSize(3)
    .recordStats()            // 打开统计
    .build();
cache.asMap().keySet();       // 存活 key ≤ 上限
cache.stats().hitRate();      // 命中率
```

## 5. 声明式缓存 @Cacheable（★★☆ 中频）

生产里绝大多数缓存只是「把方法返回值缓存起来」。用 `@Cacheable` 声明后，Spring 在方法调用前查缓存、命中直接返回，未命中才执行方法并把结果写回（Cache-Aside 模式）。

```java
@Cacheable(cacheNames = COMPUTE, key = "#id")
public User load(int id) { /* ... dbCalls++; 查库 ... */ }
// 同一 id 调两次，第二次来自缓存，dbCalls == 1
```

由 `common/config/CacheConfig` 的 `CaffeineCacheManager`（maximumSize=100、expireAfterWrite=5min）桥接。

## 踩坑

- **堆内缓存必须限大小**：不设 `maximumSize` 长期运行必 OOM。
- **TTL 是最终一致**：过期前拿到的可能是旧值，接受不了就走主动失效或 `refreshAfterWrite` 后台刷新。
- **W-TinyLFU > LRU**：命中率更高，默认就用它，别手贱改回 LRU。
- **多级缓存 / 穿透击穿雪崩**：本地(Caffeine) + 分布式(Redis) 组合挡热点；空值缓存/布隆过滤器、互斥锁/逻辑过期、随机 TTL 抖动是标配，本 demo 未展开。
- **Guava Cache 对比**：Caffeine 是继任者，API 近似但命中率与性能更优。

## 进阶方向

- 多级缓存（本地 + Redis）、`refreshAfterWrite` 后台刷新、Cache-Aside 的「写时失效」、Read-Through/Write-Through。
- `stats()` 接入 Micrometer/Prometheus 观察命中率与淘汰量。
